# Codex 提示词速查

配合[讲师手册](讲师手册.md)使用。下面的内容输入 Codex 桌面端聊天框；项目路径和可用 OpenSpec 技能应按当前环境确认。不需要安装其他 AI 编程工具，也不在聊天里粘贴凭证。

## 1. 先读项目，澄清需求

```text
需求：Agent 运行时，我希望还能输入下一条消息，后续按顺序发送。

先读取相关 OpenSpec、教学记录和现有代码，向我确认会改变方案的问题；先不要写代码。
重点确认：队列是否只在当前页面存在、取消消息是否进入历史、失败和待确认时如何处理、切换会话或身份时如何处理。
不要默认加入数据库队列、刷新恢复、跨设备管理或后台任务调度。
输出已确认范围、待确认问题和可观察的验收场景。
```

**人工要做：**确认业务行为；不能只回复“都行”，再把 AI 的假设当需求。

## 2. 固化 OpenSpec 变更

```text
把已确认的需求整理成 OpenSpec 变更，沿用当前项目的规格结构。
如果 add-conversation-message-queue 或 align-conversation-composer 已存在，先核对是否覆盖本次需求，避免重复生成。
proposal 记录范围；specs 记录行为和验收场景；design 记录复用的现有能力；tasks 记录实施与验证。
明确：待发消息不进入模型历史；客户端流结束不代表后端执行结束；工具待确认时暂停；失败保留未发消息。
先让我检查范围和验收，不要为了补齐模板增加需求。
```

**人工要做：**逐条检查可观察行为。尤其分清前端待发队列与后端执行互斥的责任。

## 3. 推进后端最小实现

```text
按确认后的规格核对或实现后端最小改动，先复用现有 AgentScope 与会话接口。
重点读取 ConversationController、ConversationSessions、AgentScopeConnection 和 DistributedSessionTurnGate。
执行状态接口必须先核对当前登录用户对会话的访问权，再读取共享租约；客户端不得传身份覆盖查询范围。
保留 /runs 的原子互斥，停止请求成功不等于租约立即释放，不新增持久化消息队列。
遵循项目 Java 约定，必要的中文日志记录会话与执行状态，不记录凭证或完整业务表单。
补充授权会话 true/false 状态和外部会话拒绝的回归，报告实际执行命令、结果和未覆盖范围。
代码已满足需求时不重写，说明依据即可。
```

**人工要做：**检查归属验证、状态来源和互斥是否仍在。状态查询和获取执行权不是同一操作。

## 4. 不会 Vue 时如何让 Codex 写前端

```text
在 phoenix-web 的现有 Vue 页面实现同一需求。先读 src/pages/conversation/index.vue、useConversation.ts、src/api/conversation/index.ts 和相关测试，沿用当前组件与样式。

交互：运行中可继续输入，发送后默认进入待发列表；待发消息可取消；未发消息不进入运行历史。
接口：复用既有 API 封装；派发前核对 /execution，running=true 时等待；停止后首次新消息也不能直接抢跑。
边界：执行失败或状态查询异常时保留未发消息并暂停；待确认 interrupt 不能被自动批准；切换身份、会话和卸载时隔离旧回调。
禁止为了展示效果伪造真实服务成功，不另建框架或改成持久化队列。
先运行相关回归，再检查类型；能做浏览器验证时检查真实组件的输入、取消、等待与失败状态，明确哪些接口使用模拟数据。
输出变更文件、测试证据和我需要确认的交互规则。
```

**人工要做：**描述状态和接口限制；不要把“看着像 Codex”当成需求的全部。

## 5. 对抗性审查与修复

```text
对当前实现做一次有证据的审查，优先找能推翻核心假设的场景。
重点检查：客户端 isStreaming=false 是否会被当成后端已释放；停止后空队列立即发送；待确认暂停；取消、失败和身份切换。
每项问题说明触发条件、实际依据、影响和最小验证方式。证据不足时标为待验证疑点，不把猜测写成缺陷。
确认缺陷后补回归：服务端仍忙时没有第二个 /runs；释放后新消息才发送；消息内容、顺序和未发保留符合规格。
不要删除互斥、固定 sleep、无限重试或修改验收标准来消除失败。
修复后重跑受影响检查，并说明剩余风险。
```

**人工要做：**检查反例是否成立，先排除测试探针或接口字段错误。

## 6. 验收与交接

```text
按 OpenSpec 场景逐条核对交付，区分本次实际执行、仓库历史证据和未执行项。
不要把类型检查、任务勾选、模拟截图或 OpenSpec 格式校验写成真实联调通过。
报告每个场景对应的断言、命令或操作、版本、环境、结果和证据位置。
需求变化时先确认业务规则，再更新规格；业务验收完成后才同步主规格并归档。
交接只补充当前分支、阻塞、未完成验证和下一步；长期背景链接到规格和工程记录。
```

**人工要做：**判断证据是否覆盖需求，并决定剩余风险能否接受。

## OpenSpec 调用提醒

自然语言任务可以由现有 Codex 工作流处理。显式调用时，先确认项目已经初始化并提供相应技能；终端运行 `openspec ...`，聊天中调用项目生成的技能。[官方调用说明](https://github.com/Fission-AI/OpenSpec/blob/main/docs/commands.md)

不要凭教程假定每个项目都有同一组快捷命令。`verify` 属于可选扩展，检查规格与实现的一致性，实际测试仍需单独执行。
